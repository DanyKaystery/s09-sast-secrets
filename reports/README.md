# Сохранённые первичные результаты

`semgrep-before.json` — raw JSON Semgrep CE 1.175.0: восемь сигналов, три разобранных C#-файла, `errors: []`. Команда из корня объекта:

```text
semgrep scan --config semgrep.yml --metrics=off --disable-version-check --no-git-ignore --json --output reports/semgrep-before.json src
```

Без `--error` Semgrep возвращает 0 при завершённом сканировании даже с находками. Ноль в exit code не является вердиктом о безопасности.

В raw JSON поле `extra.lines` может содержать `requires login`. Для занятия регистрация не нужна: используйте `path` и `start.line`, чтобы открыть локальный исходник. Это поведение формата результата CE, а не ошибка разбора.

`gitleaks-history.json` — raw JSON Gitleaks 8.30.1 для отдельного клона bundle. Команда в среде подготовки:

```text
gitleaks git /tmp/rbpo-s09-work/clone --config .gitleaks-training.toml --log-opts=--all --redact --report-format=json --report-path=reports/gitleaks-history.json --no-banner
```

Фактический путь к конфигурации при подготовке передан абсолютным путём из корня Notes API; смысловая область — клон bundle. Сканер возвратил 1: найдена одна фиктивная запись. Сканирование текущего дерева того же клона (`gitleaks dir`) вернуло 0 находок и exit 0. Gitleaks может показывать «2 commits scanned»: это число обработанных patch-наборов, а не обязательное число коммитов в `git log` (их три).

`provenance.json` связывает эти результаты с файлами исходного объекта по SHA-256 и с Git-коммитами fixture. Команда отчёта SAST охватывает только `src`, не тесты/документацию/бинарный bundle. Git-проверка охватывает только отдельную тренировочную историю; это разные объекты и версии.

Пути в raw JSON не переименованы, строки и выводы не сочинены вручную. При повторении пишите в `local/`, а не поверх первичных результатов. Raw-отчёт содержит сигнал; статус и обоснование записываются человеком отдельно. Поскольку правила не анализируют все свойства C#, отсутствие сигнала не подтверждает безопасность всего приложения.
