# Реестр решений по сигналам

Реестр связывает сигналы анализаторов с проверенным контекстом кода. Несколько сигналов с одной причиной не считаются отдельными дефектами.

## F-01. SQL-инъекция в поиске заметок

- **Источник:** Semgrep `sql-commandtext-concat` и `sql-commandtext-assignment` в `NotesRepository.Search`.
- **Статус:** подтверждённый дефект, исправлен.
- **Риск:** параметр запроса `q` достигал SQL-команды через конкатенацию. Payload `%' OR 1=1 -- ` отменял ограничение по владельцу и позволял Alice получить заметку Bob.
- **Решение:** запрос переведён на параметры `$owner` и `$pattern`; пользовательские значения передаются как данные.
- **Свидетельство до:** тест `Search_Injection_Does_Not_Return_Bobs_Note` завершился ошибкой — в результате присутствовали заметки Alice и Bob; Semgrep показал оба связанных сигнала.
- **Свидетельство после:** все 5 тестов прошли; `sql-commandtext-concat` исчез при повторном запуске Semgrep.
- **Остаточный риск:** широкое правило по-прежнему отмечает само присваивание `CommandText`; его результат разобран в F-02.

## F-02. Присваивания SQL-команд

- **Источник:** четыре сигнала Semgrep `sql-commandtext-assignment` в `NotesRepository.cs`.
- **Статус:** проверено, отдельных дефектов не подтверждено после исправления F-01.
- **Интерпретация:** правило намеренно отмечает любое присваивание SQL. Создание таблицы и подсчёт строк используют статический текст, а `Search` и `Add` передают значения через параметры.
- **Решение:** правило не отключается и не подавляется ради нулевого результата; оставшиеся сигналы сохраняются как точки ручного контроля.
- **Свидетельство:** в отчёте после исправления остаются строки 27, 35, 48 и 62, но узкого сигнала конкатенации больше нет.

## F-03. Строка `password`

- **Источник:** Semgrep `password-field-literal` в `Signals.IsPasswordFieldPresent`.
- **Статус:** ложное срабатывание в данном контексте.
- **Интерпретация:** значение `"password"` является именем поля формы. Оно не содержит пароль, токен или иной секрет и не предоставляет полномочий.
- **Решение:** код не изменяется; обоснование сохраняется в реестре.

## F-04. MD5 для ключа кеша

- **Источник:** Semgrep `weak-hash-md5` в `Signals.CacheKey`.
- **Статус:** неприменимо к заявленному назначению, требуется повторная оценка при изменении назначения.
- **Интерпретация:** хеш используется как идентификатор ключа кеша, а не для хранения пароля, подписи или доказательства целостности. В текущем API метод не вызывается.
- **Решение:** не считать криптографической защитой. Если значение начнёт участвовать в аутентификации или проверке целостности, заменить алгоритм и пересмотреть модель угроз.

## F-05. `Random` в генераторе токена

- **Источник:** Semgrep `insecure-random` в `Signals.NewAccessToken`.
- **Статус:** небезопасная реализация, недостижимая в текущем API.
- **Интерпретация:** `System.Random` не подходит для токена доступа, однако метод сейчас не связан с HTTP-маршрутами и не вызывается приложением.
- **Решение:** не использовать метод для выдачи полномочий; до его подключения заменить источник случайности на криптографический. Сигнал не скрывается и остаётся видимым как ограничение.

## F-06. Учебный токен в Git-истории

- **Источник:** Gitleaks `rbpo-training-token` в отдельной истории `fixtures/secret-history.bundle`.
- **Статус:** подтверждённое совпадение учебного правила; значение фиктивное и не является действующим секретом.
- **Интерпретация:** текущее дерево чистое — 0 сигналов; в полной истории найден 1 ранее удалённый токен. Значение в отчёте замаскировано.
- **Решение:** внешний отзыв и переписывание истории не требуются, поскольку это изолированная учебная фикстура. Для реального секрета сначала потребовались бы отзыв/ротация и проверка последствий, а очистка истории выполнялась бы после этого.
- **Свидетельство:** правило `rbpo-training-token`, файл `demo-settings.env`, строка 1, исторический commit `34d695f7967849875928173c3d4c03c8dc20c52e`.
